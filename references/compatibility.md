# 新款小米与其他安卓电视：兼容性评估

评估日期：2026-11-01。结论：**连接过滤与最终规则具备跨设备复用基础；目前不能把整套方案宣传为所有安卓电视直接通用。** 需要分别核对系统版本、CPU、视频应用版本、连接授权和开机恢复。

## 已验证与未验证

| 环境 | 证据类型 | 结论 |
|---|---|---|
| MiTV4A / Android 6.0.1 | 真实电视、用户播放确认 | 桌面视频、独立芒果、云视听及银河奇异果通过；完整重启通过 |
| AOSP Android 14 / API 34 / arm64-v8a | 本次隔离模拟运行 | 官方 arm64 CMFA 与原版助手可安装；连接过滤、纯 IP 域名识别及正常系统重启恢复通过 |
| 新款小米、其他品牌安卓电视 | 条件评估 | 有复用基础，仍需核验厂商固件、授权入口与实际视频应用；未作品牌真机认证 |
| Android 15 / API 35，首次安装助手 0.1.0 | 实际 APK 声明 + 官方安装规则 | 助手 targetSdk=23 低于默认安装门槛 24，不能原样按普通安装流程部署 |
| Android 16 及更高版本 | 未运行验证 | 单独核对当前安装及后台策略，不由本次结果外推 |

Android 14 使用的是 **AOSP 手机系统镜像，以横屏运行**，不是 Google TV、Android TV 或任何厂商电视固件。没有在模拟器播放爱奇艺、芒果、腾讯的实际影视内容，因此不把连接测试写成这些平台在新电视上的去广告认证。

## Android 14 实际测试

安装[官方 v2.11.36 发行](https://github.com/MetaCubeX/ClashMetaForAndroid/releases/tag/v2.11.36)中的 `CMFA 2.11.36.Meta / arm64-v8a`，核验官方 SHA-256：

```text
7da3083c16af676f9a3e478e3f42098b91803cbd7cb637bff4117d4d50360f95
```

使用仓库原版启动助手 0.1.0、同一套最终 14 条规则及隔离的无账号网络探针：

| 检查 | 观察结果 |
|---|---|
| 正常 HTTPS 页面 | 过滤前后均 HTTP 200 |
| 广告域 HTTP 请求 | 过滤日志明确命中该广告域 REJECT |
| 直接连接公网 IP、HTTP Host 携带广告域名 | 过滤前收到 HTTP 响应；过滤后连接结束，日志识别域名并 REJECT |
| 系统连接状态 | 探针确认 VPN 已连接 |
| 正常系统重启 | 校验开机标识已变化；助手自动发起启动，约开机 12 秒出现 Sniffer 就绪日志 |
| 重启后再次发起网络请求 | 正常 HTTPS 仍 200，广告域与纯 IP 请求仍 REJECT；未手动打开过滤工具 |

这是通用安卓层面的功能验证。正常系统重启已测试，任意时点强制断电、长期待机唤醒、视频 DRM 与厂商后台清理行为仍需目标设备验证。系统首次连接授权必须完成并确认保存，服务存在与过滤就绪分别验收。

## 部署前的明确适配门槛

### 1. 按系统支持的 ABI 选包

```sh
adb -s "$SERIAL" shell getprop ro.build.version.sdk
adb -s "$SERIAL" shell getprop ro.product.cpu.abilist
```

本次模拟系统只支持 arm64-v8a，因此使用官方 arm64 包。老电视案例的 armeabi-v7a 包只作为该机型的已验证包；不能因同属小米品牌就固定使用它。自有助手为 Java 代码，没有原生 CPU 库。

### 2. 当前助手的新版系统边界

仓库助手 0.1.0 声明 minSdk=23、targetSdk=23。[Android 14 最低可新安装目标为 23](https://developer.android.com/about/versions/14/behavior-changes-all#minimum-target-api-level)，本次安装已通过；[Android 15 默认最低目标为 24](https://developer.android.com/about/versions/15/behavior-changes-all#minimum-target-api-level)，当前助手不满足普通新安装条件。

遇到 API 35 时停止原版助手安装步骤，先评估系统原生恢复能力，或使用另行适配并验证的助手版本。本仓库未发布新版助手兼容声明；仅修改目标版本数字不等于完成运行验证。视频应用也应使用目标电视官方兼容版本，不直接搬用老电视的 APK。

### 3. 其他品牌桌面

当前助手的“返回桌面后检查”只匹配 `com.mitv.tvhome`。服务连接时的启动检查在本次 AOSP Android 14 正常重启中已验证；其他品牌的返回桌面触发需要识别其实际桌面包名，并在适配版中测试。

### 4. 新系统的授权与恢复选择

依据[官方 VPN 文档](https://developer.android.com/develop/connectivity/vpn#always-on)，Android 7 起提供系统常开 VPN 能力；若目标固件提供入口且应用支持，可评估该路径并做重启验收。该官方能力不等于所有电视品牌都提供相同界面。

Android 13 起的部分安装方式还可能涉及[受限设置与辅助功能授权](https://support.google.com/android/answer/12623953?hl=en)。沿用用户授权边界，保留其他辅助功能服务；不把关闭系统保护作为通用部署步骤。

### 5. 广告规则与应用版本

**条件判断：**若目标视频应用仍连接相同广告域，且流量实际进入过滤通道，最终规则可以复用。应用、地区或投放接口改变时，依据目标设备实际连接更新规则并重新验收。设备品牌本身不能证明规则覆盖率。

其他电视没有完成实际播放和重启验证前，只标记“具备适配条件”或“已通过通用系统模拟验证”，不标记“该品牌全系去广告成功”。
